# Nautilus trading core handoff

## Working slice

The optional trading extra pins the actual native NautilusTrader 1.221.0 runtime. The adapter accepts the existing pure Strategy protocol and canonical BarDataset. It registers the four paper instruments as local CurrencyPair objects and uses only a Nautilus SimulatedExchange named PAPER. It imports no agent/provider module and requires no model or broker credentials.

Replay translates each bar into an open quote and a logical close quote one nanosecond later. The plugin receives only completed prior bars when the next open quote arrives. This is an explicit synthetic execution model, not reconstructed historical order-book or intrabar liquidity. Long/flat targets follow the existing plugin contract. Native orders, fills, commissions and positions are generated by Nautilus and checked against the fill ledger.

Slippage is an adverse synthetic half-spread in basis points. Bid/ask rounding is adverse at instrument tick precision: 5 decimals for USD-quoted pairs, 3 for JPY-quoted pairs. Source precision loss and unrepresentable fixed fees are rejected. Positive fees use Nautilus FixedFeeModel per order; zero fees use its zero per-contract model. Quote sizes are a fixed synthetic capacity of 1,000,000 units. Initial balances/leverage are simulation inputs and grant no live authority.

The adapter owns a fresh 28-digit Decimal context, so caller precision/trap changes cannot change results. Timestamps use integer UTC nanoseconds without floating-point conversion. Results retain the dataset fingerprint, raw CSV SHA-256, versioned strategy reference, costs, native fills, native order count and final position. Random IDs and wall time are excluded from deterministic results.

net_pnl is exact Decimal cash flows from native fills plus the final canonical close mark. native_realized_pnl is Nautilus's realized value rounded to account currency precision and excludes unrealized positions. They can differ and are not interchangeable. No forced liquidation is invented at replay end.

## Files and commands

nautilus_runtime.py contains the adapter/result contract. strategy_samples.py provides trusted buy-and-hold and moving-average-cross examples with version 1.0.0 references. They demonstrate interfaces without a trading-performance claim. nautilus_cli.py reads one bounded canonical CSV without loading arbitrary client code. The artifact schema is docs/schemas/nautilus-result.schema.json.

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,data,trading]"
ai-quant-backtest tests/fixtures/nautilus_replay.csv --strategy moving-average-cross --slippage-bps 10 --fee 0.10 --output docs/evaluations/nautilus-sample-result.json
python scripts/benchmark_nautilus.py --output docs/evaluations/nautilus-native-baseline.json
python -m pytest -q tests/test_nautilus_runtime.py tests/test_strategy_samples.py
python -m pytest -q
```

The recorded local baseline runs 1,000 synthetic bars three times and checks exact result equality. It records observed latency/platform details, not an SLA or live performance estimate. A sample artifact was generated through the installed console runner and validated against its JSON Schema.

CI adds Windows/Linux jobs installing the trading extra and asserting the exact runtime version before testing. Hosted jobs have not run. Base installs skip the optional native test module; the dedicated job cannot silently omit the dependency.

## Remaining P03 gates

Independent critical review, hosted cross-platform CI evidence, immutable strategy implementation manifests, isolation for untrusted plugins, direct tick/catalog replay, historical spread/depth/latency models, multi-instrument simulation, short targets and the complete strategy harness remain open. Current plugins are trusted Python receiving full history; large-replay memory/CPU behavior needs a streaming contract before scale. The paper order API retains its separately gated simulator; this adapter does not replace the Risk Kernel or broker gateway. Live routing remains absent.

Rollback preserves archived data and result evidence. Removing the optional dependency does not alter the paper order database. Runtime upgrades require a new pin and replay comparison.
