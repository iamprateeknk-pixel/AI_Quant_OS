# Demo and shadow position direction comparison

The operator-protected `GET /api/v1/paper/shadows/{shadow_id}/demo-position-comparison?sequence=N` endpoint reports a descriptive direction comparison between the instrument position produced by one retained shadow report and the latest local Exness MT5 demo portfolio observation.

The endpoint reads the demo record from the server-configured demo sync directory and loads the shadow report from the verified shadow archive. It only reports positions when the demo portfolio observation timestamp exactly matches the last source-bar timestamp in the selected report and the demo's declared history window covers the complete shadow source-bar interval. A time mismatch returns `WITHHELD` with `SOURCE_TIME_MISMATCH`; incomplete interval coverage returns `WITHHELD` with `HISTORY_WINDOW_MISMATCH`. Both states omit position values. The response records the shadow interval and demo history window alongside the endpoint observation times, source receipt, shadow hash, candidate report hash, and genome hash. An unavailable or stale demo portfolio is a service error. The response is uncached.

The signed shadow value is in abstract strategy-model units. The signed demo value is in broker quantity units derived from current symbol contract metadata. Those units are incompatible, and the response never subtracts or equates their magnitudes. It compares direction only and explicitly reports `magnitude_comparison: NOT_AVAILABLE`. A separate inventory-presence field distinguishes `DEMO_HEDGED_NEUTRAL` from flat when BUY and SELL positions net to zero; inventory presence is still reported when timestamp mismatch withholds position quantities. The demo source remains `UNVERIFIED` and observations are `NON_ATOMIC_SEQUENTIAL_READ`.

The output is not proof that the candidate generated or owns broker orders. It contains no PnL, financing, fill, latency, or causal attribution and grants no order or promotion authority. The API must not be described as a live-broker execution comparison. Production broker history linkage and production source ingestion remain open.

## Per-bar demo position coverage

The operator-protected `GET /api/v1/paper/shadows/{shadow_id}/demo-trajectory-comparison?sequence=N` route compares position direction at each source-bar timestamp in the selected report. It reconstructs shadow direction from the cumulative native shadow fills and joins only to an audited demo sync projection snapshot captured at the exact same timestamp. The API binds the projection read to the account-scope reference from the current fresh portfolio publication, requires its receipt to match the projection head, and checks the publication again after the projection read.

The versioned history report returns one row per shadow source bar and a `COMPLETE`, `PARTIAL`, or `NONE` coverage state. A bar without an exact demo capture is `WITHHELD / NO_EXACT_DEMO_SNAPSHOT`; it is never filled from the nearest capture or carried forward. Broker quantity units from current symbol metadata and strategy-model units remain separate; the report compares direction only and marks magnitude unavailable. Every row carries the source receipt reference when a match exists. The report retains candidate, genome, shadow, and demo account-scope identity, and fixes causal, promotion, order, and portfolio authority false.

The strict response schema is `docs/schemas/demo-shadow-position-history-comparison-v1.schema.json`. The projection read verifies the complete retained projection/audit chain before returning snapshots for the published account scope. Reads remain sequential and non-atomic, and native history attestation remains unverified. Exact per-bar matching may legitimately produce partial or no coverage.

The single-position schema is `docs/schemas/demo-shadow-position-comparison-v1.schema.json`. Tests cover direction classification across distinct units, hedged-neutral versus flat inventory, inventory presence during timestamp mismatch withholding, incomplete history-window refusal, failed shadow evidence, operator authorization, no-store response behavior, history projection integrity, exact per-bar coverage and both schema parity checks.

This trajectory remains for one selected shadow assignment and instrument. It does not reconcile broker fills to shadow fills, compare quantities or P&L, include financing, or establish causal ownership. It is not a complete live-broker-versus-shadow comparator. MT5 history coverage and native attestation remain unverified.
