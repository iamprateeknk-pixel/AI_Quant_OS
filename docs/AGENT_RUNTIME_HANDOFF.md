The registry and tool SDK are in agent_registry, agent_catalog and agent_permissions. The read API is `/api/v1/agents/registry`. A bounded compiler assembles paper evidence through `/api/v1/paper/agents/context`, with explicit missing inputs and source-bound validity. Protected TRAINING/HOLDOUT inputs now require a content-addressed `DatasetResourceCatalog`; authorization checks receipt-backed refs and classification before a fetch, and the context evidence commits the catalog and refs. A08 uses checked research receipts, A10 uses the checked validation package holdout receipt, and A11 uses the verified immutable holdout scope from its archived report. A09's reviewed hypothesis is a derived summary and is classified GENERAL. The research catalog stores TRAINING and HOLDOUT CSV bytes in separate SQLite files, migrates verified legacy holdout rows, and its TRAINING reader verifies HOLDOUT metadata without selecting raw HOLDOUT bytes. Both files remain under one trusted application/process identity; independently permissioned storage/process isolation and acceptance remain open.

With persistent PAPER storage, lifecycle transitions are retained in the sibling `.agent-lifecycle.sqlite3` journal. Each event binds the exact manifest ref, prior and next state, and per-version sequence to an audit chain. Startup verifies and restores the journal before serving agent capabilities; unknown versions, changed manifest pins, or corruption prevent startup. New manifest versions begin in SHADOW. Quarantine remains pinned and is restored from both the lifecycle and health journals. A17's operational outcome counts and timing summaries are reconstructed from verified graph receipts and matching event-hash-checked traces, with source digests included in the observation. Timing summaries cover only traces whose audited RUNNING-to-terminal interval is available. They do not establish accuracy, calibration, or promotion readiness. Transient in-memory app mode starts from manifest defaults, and local SQLite audit chains do not protect against an attacker who can rewrite the complete database and integrity metadata.

With AI_QUANT_PAPER_DB set, startup opens a sibling `.agents.sqlite3` file. Execute an existing archived paper context through operator-authenticated POST `/api/v1/paper/agents/execute` with run_id and context_ref. GET `/api/v1/agents/graph-runs/{run_id}` reads historical receipts without changing state. POST `/api/v1/paper/agents/graph-runs/{run_id}/resume` checks current evidence and permissions before any uninvoked call. A RUNNING reservation becomes UNCERTAIN and is never automatically replayed. COMPLETED means a trusted installed handler returned its typed advisory schema; it grants no order authority. Absent handlers return UNAVAILABLE and incomplete contexts return WAIT_FOR_DATA.

## Migration and rollback

The graph increment adds pinned LangGraph and SQLite checkpoint dependencies. Install the package into the project virtual environment with `python -m pip install -e ".[dev,data]"`. The local verification environment reuses existing system libraries without changing their installations. Roll back code without deleting any SQLite file, advisory runs, contexts, graph reservations, snapshots or audit evidence. Older binaries ignore the lifecycle sidecar; restoring newer code must verify it before serving agent capabilities. Quarantine recovery still requires a separate gated workflow. The journal is local-process SQLite, not a distributed lease or independently protected security boundary.
