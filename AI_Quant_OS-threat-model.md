# AI_Quant_OS threat model

> Refreshed 2026-10-23 for the current HOLDOUT service RPC and ingestion implementation.

> Operator-confirmed scope: local, single-operator workstation running PAPER through the loopback launcher. The operator selected the repository and execution-pack data inventory as the sensitivity basis. This is repository-grounded threat analysis, not independent security acceptance.

## Executive summary

The operator-confirmed deployment is one operator on a local workstation using the PAPER launcher; sensitivity follows the repository and execution-pack data inventory. The API and UI bind to loopback, and the PAPER router has no live broker execution route. A separate CLI can submit explicitly admitted market orders to a configured Exness demo account through a supervised MT5 worker. Highest in-scope risks are local credential/session compromise, tampering or rollback of SQLite and validation evidence, raw HOLDOUT exposure before OS isolation is accepted, manipulated market/replay inputs, local resource exhaustion, and misuse of the demo order path. Remote unauthenticated reads become high priority if the launcher or loopback boundary is bypassed. Optional provider calls and strategy worker containers add data-transfer, spend, archive parsing, and Docker isolation boundaries. Evidence anchors: `src/ai_quant_os/local_runtime.py:LocalSettings`, `src/ai_quant_os/local_api.py:_serve`, `src/ai_quant_os/api.py:create_app`, `src/ai_quant_os/broker.py:BrokerRouter`, `src/ai_quant_os/exness_demo_order_cli.py:main`, `src/ai_quant_os/mt5_demo_worker.py:supervise_demo_order`, `docs/P07_HANDOFF.md`.

## Scope and assumptions

- **In scope:** Python FastAPI backend and local launcher; Next.js operator UI and same-origin session routes; SQLite paper orders/fills, operator sessions, safety receipts and audit chain; agent/strategy admission; local data/provider integrations; candidate worker image assembly/execution; CI security and test gates.
- **Out of scope:** an unconfirmed cloud deployment, live/external broker account operations and vendor infrastructure, actual provider billing/data retention, and any live trading operation. The local Exness demo account boundary is in scope; no demo account was connected during this increment. Current source reports no live release owner or live execution route: `docs/CONTROL_OWNERSHIP.md`; the execution pack's P13 gate remains required.
- **Deployment (operator-confirmed 2026-10-20):** local single-operator workstation, PAPER mode, using the provided launcher. The API and UI bind to `127.0.0.1`; opt-in Prometheus/Grafana also bind to loopback. When both OTel and managed-Collector flags are explicitly enabled, the local app verifies and starts its pinned Collector before the API and retains rotated trace files under local state. Child environments are filtered and optional providers remain disabled by default (`src/ai_quant_os/local_runtime.py:LocalSettings.validate`, `LocalSettings.environments`; `src/ai_quant_os/local_api.py:_serve`; `src/ai_quant_os/observability_cli.py`). The threat ratings assume this launcher and do not assert that an unobserved runtime configuration matches it.
- **Data sensitivity (operator-confirmed from repository/pack inventory 2026-10-20):** operator/recovery/session credentials; paper and demo order, fill, account-like, safety, and audit records; market features; strategy source and evaluation artifacts; optional provider credentials/payloads; retained trace identities and operation metadata. Treat credentials and session material as secret, and stored trading/research and audit records as sensitive and integrity-critical. PII or regulated personal data was not identified in the reviewed project documentation; provider retention, data rights, and jurisdictional obligations remain unconfirmed (`docs/adr/0181-secrets-and-compliance-gates.md`). Local ignored environment files were not inspected.
- **Remaining context dependency:** any future shared, remote, or internet-facing deployment requires a fresh threat-model pass. Provider/data retention, licensing, and jurisdiction requirements also need owner confirmation before enabling those integrations with sensitive payloads.
- **Local-account confirmation (operator-confirmed 2026-10-21):** the Windows account is exclusive to the operator. This lowers likelihood for access by another ordinary local user; malware or a process running with that account's privileges remains in scope.

## System model

### Primary components

- **Mission Control UI:** Next.js pages and server-side API routes. Operator session cookies are `HttpOnly`, `SameSite=Strict`, and set `Secure` when the configured origin is HTTPS (`apps/web/src/features/operator-session/server.ts:cookieOptions`). The browser credential boundary validates same-origin requests and only accepts a loopback HTTP backend (`apps/web/src/features/operator-session/boundary.ts`).
- **Paper API:** FastAPI composition root creates the paper world state, risk kernel, broker router, stores, and feature routes (`src/ai_quant_os/api.py:create_app`). The supplied local API launcher binds to loopback (`src/ai_quant_os/local_api.py:_serve`).
- **Deterministic control:** `RiskKernel` validates paper intent decisions; `PaperExecutionGateway` checks kernel-issued approvals and produces simulator receipts; `BrokerRouter` rejects non-PAPER execution routes (`src/ai_quant_os/risk.py:RiskKernel`, `src/ai_quant_os/execution.py:PaperExecutionGateway`, `src/ai_quant_os/broker.py:BrokerRouter`).
- **Native research replay:** pinned Nautilus backtests consume canonical, source-bound recorded quotes. The asynchronous FX portfolio report binds fill prices and cumulative fills to the displayed top-of-book side size and carries explicit schema/replay/liquidity model identifiers; this remains a research result with no broker authority (`src/ai_quant_os/native_tick_evidence.py:canonical_tick_source`, `src/ai_quant_os/native_tick_portfolio.py:run_native_tick_portfolio`, `verify_tick_portfolio_report`).
- **Agent/strategy runtime:** typed graph contexts and registered tools run through `GraphRuntime`; architecture tests prevent agents/strategies from directly importing control modules (`src/ai_quant_os/graph_runtime.py`, `src/ai_quant_os/agent_registry.py`, `tests/test_architecture_broker_boundary.py`).
- **Local persistence:** SQLite stores paper orders/fills, operator sessions, control receipts, and audit events. The audit chain detects local event modification or loss, but is not an external immutable checkpoint (`src/ai_quant_os/order_store.py`, `src/ai_quant_os/operator_session_store.py`, `src/ai_quant_os/paper_state_store.py`, `src/ai_quant_os/audit_chain.py`).
- **HOLDOUT validator (implemented, not installed):** a Windows `LocalService` host is designed to own HOLDOUT, package, candidate-validation, and research archives. Its v4 named-pipe RPC checks bounded strict messages, verifies the server service SID client-side, limits the pipe DACL to the service SID, operator SID, and SYSTEM, and returns summaries/receipts. The API routes validation workflows through this client and the HOLDOUT CLI sends pinned raw CSV directly to the service. Installation, source-archive migration, actual service-token identity, and file/pipe ACL acceptance are still open, so this code does not establish an active OS isolation boundary (`src/ai_quant_os/holdout_validator_rpc.py`, `src/ai_quant_os/holdout_validator_service.py`, `src/ai_quant_os/holdout_service_security.py`, `src/ai_quant_os/holdout_data_cli.py`, `docs/P07_HANDOFF.md`).
- **Demo order persistence:** the standalone MT5 demo gateway uses a separate SQLite attempt table that binds the idempotency key to exact command JSON and account scope. A reservation with no terminal receipt becomes UNKNOWN and will not be submitted again automatically (`src/ai_quant_os/mt5_demo_execution.py:DemoOrderStore`).
- **Local observations:** opt-in SDK traces pass over unauthenticated OTLP HTTP on IPv4 loopback to the pinned Collector. It writes rotated JSON files under the local app state directory; Prometheus/Grafana run separately under the local observability supervisor. Trace metadata is allowlisted, and the protected API trace reader checks retained file prefixes, but local processes and users with access to the account can still read or alter these files directly (`src/ai_quant_os/paper_telemetry.py`, `infra/observability/collector.json`, `src/ai_quant_os/local_runtime.py`, `src/ai_quant_os/observability_cli.py`).
- **Optional integrations and workers:** Jev/reviewer providers are opt-in and spend-admitted; MT5 sync remains observation-only; a separate CLI can submit one explicitly admitted Exness demo market order through a supervised worker. Strategy workers are assembled from bounded, digest-pinned OCI data and executed with Docker restrictions (`src/ai_quant_os/jev_adapter.py`, `src/ai_quant_os/openai_reviewer.py`, `src/ai_quant_os/mt5_sync_service.py`, `src/ai_quant_os/exness_demo_order_cli.py`, `src/ai_quant_os/mt5_demo_worker.py`, `src/ai_quant_os/strategy_image_content.py`, `src/ai_quant_os/strategy_container_lifecycle.py`).
- **Build/CI:** GitHub Actions runs Ruff, tests, web checks, and Gitleaks. CI and developer credentials remain separate from the PAPER runtime (`.github/workflows/ci.yml`).

### Data flows and trust boundaries

- Local operator browser → Next.js UI: HTTP(S) same-origin requests carry credentials only through the session boundary; origin and host must match. Cookie flags reduce script access and cross-site submission risk. Deployment proxy/TLS configuration is not established (`apps/web/src/features/operator-session/boundary.ts`, `server.ts`).
- Next.js server → FastAPI: HTTP to a loopback-only backend origin is enforced by the web boundary and local launcher. Mutations require operator/session authorization; some paper status, order, fill, portfolio, risk, and audit reads are intentionally available without an operator token, which is safe only within the assumed local boundary (`src/ai_quant_os/api.py:822-998`, `apps/web/src/features/operator-session/boundary.ts:backendOrigin`).
- API request → deterministic paper control and SQLite: quote/bar/intent/fill/control payloads cross typed route models into world-state, risk, execution, and durable receipts. Operator mutations are authenticated; risk applies a five-second quote age limit and fixed paper limits (`src/ai_quant_os/api.py:1885-2182`, `RiskKernel` in `src/ai_quant_os/risk.py`, `PaperExecutionGateway` in `src/ai_quant_os/execution.py`).
- API → optional local Collector → trace files: when explicitly enabled, the API emits bounded OTLP protobuf to a loopback receiver with no receiver authentication. The Collector applies its memory limiter and writes rotating trace JSON. Span attributes use route templates, fixed methods/status/outcomes and selected internally generated identifiers; raw URLs, request bodies, credentials and exception text are excluded. Any local process can submit forged spans or consume Collector capacity, and the trace files are not an audit journal or tamper-proof evidence (`src/ai_quant_os/paper_telemetry.py`, `infra/observability/collector.json`, `infra/observability/collector-release.json`).
- Recorded archive → native replay CLI: bounded CSV/archive input is canonicalized before Nautilus runs; output source snapshots and fills are then independently reconciled. The report prevents fills from exceeding the quote-side size supplied by that same source, while source authenticity and actual venue depth remain outside this boundary (`src/ai_quant_os/tick_portfolio_cli.py`, `src/ai_quant_os/native_tick_evidence.py`, `src/ai_quant_os/native_tick_portfolio.py`).
- API → agents/strategies: the server compiles source-bound contexts, enforces registry/tool permissions and validates output models. Agent/strategy modules cannot directly import broker/execution control modules; indirect runtime behavior still needs broader independent review (`src/ai_quant_os/graph_runtime.py`, `src/ai_quant_os/agent_permissions.py`, `tests/test_architecture_broker_boundary.py`).
- Backend → external providers/data services: when explicitly enabled, paper market features or compact review evidence may be sent to external providers; credentials are server-side and provider spending is reserved before calls. Actual invoice correspondence and provider retention are not established (`src/ai_quant_os/jev_adapter.py`, `src/ai_quant_os/openai_reviewer.py`, `src/ai_quant_os/provider_spend_store.py`).
- Operator CLI → supervised MT5 demo worker → local terminal → Exness demo service: enrollment and one strict order command plus the demo password cross from the shell to a bounded child process over local stdin/stdout pipes; the worker filters inherited `AI_QUANT_MT5_*` variables, verifies the expected account is DEMO, then calls `order_check` and `order_send`. SQLite reserves the idempotency key before submission and binds it to command and account scope. The pipe and SQLite are local to the same OS account and are not an OS privilege boundary; terminal custody is unverified and unknown outcomes are not reconciled automatically (`src/ai_quant_os/exness_demo_order_cli.py:main`, `src/ai_quant_os/mt5_demo_worker.py:encode_order_request`, `supervise_demo_order`, `worker_request`, `src/ai_quant_os/mt5_demo_execution.py:DemoOrderStore`, `submit_demo_order`).
- Operator CLI → Docker worker: an operator-selected validation package and pinned image inputs cross into a container with network disabled, read-only root, non-root user, dropped capabilities, and bounded CPU/memory/processes. Archive sizes are bounded. Docker daemon, host kernel, and local workspace remain in the trust base (`src/ai_quant_os/strategy_container_cli.py`, `src/ai_quant_os/strategy_container_lifecycle.py`, `src/ai_quant_os/strategy_image_content.py`).
- HOLDOUT operator CLI → validator service: the CLI sends a pinned CSV and verified TRAINING receipt metadata over the bounded v4 Windows named pipe. The service is intended to write and verify raw HOLDOUT data under its protected directory and return receipt metadata only; the service is not installed or accepted under its Windows identity in this checkout. The operator SID is explicitly permitted by the pipe ACL, so same-account malware can attempt the same RPC operations if the service is installed (`src/ai_quant_os/holdout_data_cli.py`, `src/ai_quant_os/holdout_validator_rpc.py`, `src/ai_quant_os/holdout_validator_service.py`, `src/ai_quant_os/holdout_service_security.py`).
- Paper API → validator service: A10/A11 context, package, validation, and publication operations cross a versioned local RPC. Raw HOLDOUT remains service-owned and the API receives bounded summaries and opaque evidence references. This boundary depends on the service installation and ACLs that have not yet been accepted (`src/ai_quant_os/validation_scientist_api.py`, `src/ai_quant_os/holdout_validator_rpc.py`, `src/ai_quant_os/holdout_validator_service.py`, `docs/P07_HANDOFF.md`).
- Developer changes → GitHub Actions: source and dependency configuration are tested and scanned for committed secrets. CI results do not prove production deployment isolation or third-party terms (`.github/workflows/ci.yml`).

## Attacker model

### Capabilities

- A remote unauthenticated actor if the API or UI is exposed beyond the loopback launcher.
- Malware or a process running with the operator's privileges on the confirmed workstation; an unprivileged user on a separate shared staging host is a conditional deployment scenario, not the confirmed workstation model.
- A user able to submit malformed or stale market/agent/strategy inputs through an authorized workflow.
- A process running with the operator's workstation privileges can alter CLI inputs or interfere with the local terminal and worker when the demo-order workflow is launched.
- A process running as the exclusive operator can connect to the HOLDOUT pipe because the intended DACL includes that user's SID; the service's strict schemas and aggregate-only replies reduce impact but do not distinguish the PAPER API from another process under the same account.
- A malicious or compromised provider, data package, strategy source, or dependency within the limits of its enabled integration.
- A contributor who can submit source changes to the CI pipeline, subject to repository protections not verified here.

### Non-capabilities

- The PAPER router has no live broker execution path or live release owner; it rejects non-PAPER routes. The separate CLI is limited to a configured Exness demo account and does not add demo or live routing to PAPER (`src/ai_quant_os/broker.py:BrokerRouter`, `src/ai_quant_os/exness_demo_order_cli.py`, `docs/CONTROL_OWNERSHIP.md`).
- Agent and strategy outputs cannot directly authorize risk or import broker/execution control modules (`src/ai_quant_os/agent_permissions.py`, `tests/test_architecture_broker_boundary.py`).
- The provided local launcher does not expose the API on a public interface; this non-capability is conditional on that launcher being used (`src/ai_quant_os/local_runtime.py`, `src/ai_quant_os/local_api.py`).
- No live account credentials or actual local secret values were inspected, so their presence and compromise are not assumed.
- The HOLDOUT service's OS boundary is not treated as an active control: the host is implemented but uninstalled and process/file ACL acceptance is outstanding (`docs/P07_HANDOFF.md`, `docs/adr/0222-windows-holdout-validator-identity.md`).

## Top abuse paths

1. **Expose unauthenticated paper reads:** misconfigure the API on a reachable interface → remote actor queries orders, fills, positions, strategy/evidence or audit endpoints → disclose operational and research data.
2. **Steal operator authority:** compromise workstation/environment or expose session/token handling → call authenticated quote, intent, recovery, or safety routes → corrupt paper state and evidence; a separate local demo-order invocation may also alter demo account state, with no live order path observed.
3. **Poison paper inputs:** authorized or compromised client submits manipulated quotes/bars/fills → resulting paper world state and evaluation evidence are misleading; freshness and risk checks reduce but do not establish source truth.
4. **Rewrite local history:** obtain write access to SQLite/state files → alter data and recompute a local hash chain or restore an older consistent database → hide or falsify local paper history; no remote checkpoint currently anchors the chain.
5. **Abuse candidate processing:** provide a crafted archive or hostile strategy worker → exploit a parser, Docker/host boundary, or resource limit → compromise the local operator host or exhaust resources; bounded archives and constrained worker settings reduce exposure.
6. **Leak data or incur spend through providers:** obtain provider enablement/credential or alter its configuration → send market/review evidence to the vendor and consume paid capacity → disclose data or create cost; opt-in settings and spending reservations reduce but do not prove provider retention or invoice correspondence.
7. **Exhaust local service capacity:** submit expensive API/agent/research workloads or large valid inputs → consume CPU, memory, SQLite locks, or disk → paper UI/service unavailable; no deployment-wide rate limit or resource budget was confirmed.
8. **Misuse the demo order path:** obtain same-account process access or cause the operator to run a tampered command/configuration with the explicit submission switch → the supervised worker submits a bounded market order to the enrolled DEMO account → demo positions and research evidence become misleading; real-capital orders are not authorized by this CLI or the PAPER router.
9. **Corrupt validation evidence through the service boundary:** compromise a process under the operator account → connect to the operator-SID-authorized pipe and submit permitted HOLDOUT or validation operations → alter which dataset is treated as HOLDOUT or consume service capacity, weakening evidence integrity; the service validates pins, receipts, overlap, and schemas, but the pipe does not separate same-account processes and installation/ACL behavior is unaccepted.

## Criticality calibration

Severity and priority below use the operator-confirmed single-operator local PAPER deployment. Likelihood reflects the exclusive workstation account and loopback launcher; impact reflects loss of sensitive research/evidence, service availability, or the explicitly enabled demo account. High-impact events with an uncommon prerequisite are medium priority; a credible exposure path can raise priority. A runtime configuration that exposes the API beyond loopback, or adds users, raises likelihood for API and credential threats.

- **Critical:** credible unauthorized real-capital execution, or compromise of production broker credentials with order authority. Neither live execution nor a production release owner was found, so these are future-release examples and current scope has no critical-rated finding.
- **High:** likely compromise of operator control with persistent safety-state changes; or reachable unauthenticated access to sensitive order/audit data. Examples include a stolen recovery token used for control changes and a misconfigured API exposed beyond loopback.
- **Medium:** integrity loss after same-account or host compromise; manipulated market/replay inputs; provider data or cost exposure; local resource exhaustion; worker isolation failure; or unintended demo orders. Examples include altered SQLite evidence, exhausted research workers, and a demo position created by tampered command input.
- **Low:** bounded malformed inputs rejected by schemas and minor disclosure of non-sensitive local health metadata. Examples include a single rejected quote payload or isolated status metadata exposure with no path to orders, credentials, or research records.
